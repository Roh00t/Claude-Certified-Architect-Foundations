Three ideas that run through every domain

The exam is judgment, not trivia. Almost every question is: given this production problem, which fix targets the real root cause? Internalize these three and most answers fall out on their own.

1

Guarantees beat instructions

When a rule MUST hold — verify identity before a refund — enforce it in code: hooks, gates, schemas. Prompts are probabilistic; they fail a small % of the time.

2

Fix the root cause, proportionately

Vague tool descriptions? Improve the descriptions — don't build a routing classifier. The exam loves over-engineered distractors.

3

Context is scarce and leaky

The window fills up, the middle gets lost, summaries drop the numbers. Extract key facts, trim tool outputs, pass information explicitly between agents.

Trap Map — how the exam gets you to pick the wrong answer

Every distractor on this exam belongs to a family. Name the family and the option dies. After any answer in drill/sweep modes, the trap chips below the rationale tell you which families were in play.

The eight distractor families

  • PROMPT-HOPE — offers a system-prompt line or few-shot examples where the scenario says a rule must always hold. Cue words in the stem: "guarantee", "compliance", "never", "financial consequences" ⇒ the answer is a hook, gate, or schema. Prompts are probabilistic.
  • OVER-ENGINEERING — a routing classifier, separate trained model, fine-tuning, or "higher-tier model with bigger context" where improving a description or criteria fixes the root cause. Cue: "most effective first step" ⇒ cheapest root-cause fix wins.
  • NONEXISTENT FEATURE — plausible-sounding flags/options that don't exist: --batch, CLAUDE_HEADLESS, inherit_context: true, parallel: true, context: compact, a commands array in config.json. If you've never seen it in the docs, it's bait.
  • SILENT SUPPRESSION — returning empty-as-success, discarding a conflicting value, hiding an error, "add a footnote". Information destruction is never the answer.
  • DISPROPORTIONATE — terminate the whole workflow, escalate everything, review 100% forever, reject the document class. The exam rewards graduated responses with partial results.
  • HEURISTIC GUESS — pick the most recent / most prestigious / average the two. The answer is always: ask for identifiers, or keep both values annotated with attribution.
  • BURDEN-SHIFT — "require developers to split PRs", "ask the customer to resend one issue at a time". Fixing the humans instead of the system loses.
  • WRONG PROBLEM — a genuinely good practice that doesn't address the failure described. Q7-style: subagents blamed when the coordinator's decomposition was narrow. Re-read what the logs actually show.

Tie-breakers when two options both look right

  • "Most effective first step" ⇒ lowest-effort root-cause fix (descriptions before few-shot before architecture).
  • "Must / guarantee / compliance" ⇒ programmatic over prompt, always.
  • Prefer the option that preserves information (partial results, both values, structured context) over any that destroys it.
  • Prefer the option that keeps separation of concerns (coordinator routes; scoped tool for the 85% case) over full access or bypassing.
  • If an option solves the problem and adds new infrastructure, look for one that solves it without the infrastructure.
